1. Resum Teòric: Framework i Arquitectura

Què és Flutter?

Flutter és un framework de codi obert creat per Google per desenvolupar aplicacions natives multiplataforma (Android, iOS, Web, Desktop) des d'una única base de codi.

  • Llenguatge: Utilitza Dart, un llenguatge orientat a objectes, fortament tipat i optimitzat per a la creació d'interfícies ràpides.
  • Hot Reload: Permet veure els canvis en el codi de manera immediata (sub-segon) sense perdre l'estat actual de l'aplicació.
  • Control total de píxels: Flutter no utilitza els widgets natius del sistema operatiu; dibuixa directament la interfície en pantalla utilitzant el seu propi motor de renderitzat d'alt rendiment (Impeller a les darreres versions / Skia).

Arquitectura interna d'arbres (Trees)

Flutter gestiona la interfície d'usuari de manera extremadament eficient dividint-la en tres arbres paral·lels:

  • Widget Tree: La configuració immutable de la UI ("el que volem veure").
  • Element Tree: El lligam estructural entre el Widget i el seu estat. És la referència real de la vista i gestiona el BuildContext.
  • RenderObject Tree: L'arbre encarregat de calcular posicions, mides i pintar realment els píxels en pantalla.

StatelessWidget vs StatefulWidget

La gestió de la interfície es divideix segons si els components han de canviar dinàmicament o no:

Immutable (Sense Estat)

StatelessWidget

Widgets la interfície dels quals no canvia en temps d'execució una vegada construïts (ex. un text fix, una icona o un botó estàtic).

2. La Filosofia de Flutter: "Everything is a Widget"

A diferència d'altres opcions de desenvolupament mòbil on s'intercanvia la interfície mitjançant fitxers XML/HTML i l'estat en fitxers de codi separat, en Flutter absolutament tot és un Widget.

🧱 L'Analogia del Joc de LEGO:

Imagina que desenvolupar una aplicació mòbil és com construir un castell de LEGO. No pots crear peces de la nada; utilitzes blocs preexistents de diferents mides, colors i funcionalitats. Un bloc pot ser una peça bàsica (un Text o un Icon), o pot ser una placa base que aguanta altres peces (un Row o una Column).

Si vols canviar el color d'una estructura, no pintes el bloc directament: l'embolcalles o el substitueixes per un altre bloc que defineixi aquesta funcionalitat. Combinant i anidant aquests blocs en una jerarquia d'arbre, es construeixen des dels botons més senzills fins a les pantalles més complexes.

  • Widgets Visuals: Text, Image, Icon, ElevatedButton.
  • Widgets de Disposició / Layout: Row, Column, Stack, Padding, Center.
  • Widgets d'Estructura / Estil: Scaffold, MaterialApp, Theme, MediaQuery.

3. Sistema de Disseny: Material 3 (M3)

Material 3 (també conegut com Material You) és l'última versió del sistema de disseny de Google. Flutter el va adoptar com a estàndard per defecte a partir de les seves darreres versions de producció.

Per què s'utilitza?

  • Personalització Dinàmica: Permet generar paletes de color completes harmonioses a partir d'un únic color base (seedColor).
  • Components Adaptatius i Moderns: Ofereix botons amb cantonades més arredonides, targetes sense ombres exagerades i navegació flotant millorada.
  • Accessibilitat integrada: Garanteix nivells de contrast de text, mides de cerca de fitxers i zones de contacte tàctil homologades per a usuaris amb necessitats especials.

Com s'activa en Flutter?

Només cal instanciar el paràmetre useMaterial3: true (habilitat per defecte) dins del tema general de l'aplicació:

MaterialApp(
  title: 'La meva App PMDM',
  theme: ThemeData(
    useMaterial3: true,
    colorScheme: ColorScheme.fromSeed(
      seedColor: Colors.deepPurple,
      brightness: Brightness.light,
    ),
  ),
  home: const HomeScreen(),
);

4. Classes Fonamentals per a la Interfície

Abans de construir widgets complexos, cal conèixer les classes auxiliars que defineixen la geometria, els espaiats i l'aparença visual:

  • Color i ColorScheme: Permet definir valors cromàtics mitjançant paletes predefinides (Colors.blue), codis hexadecimals (Color(0xFF42A5F5)) o canals de transparència (Color.fromRGBO(255, 0, 0, 0.5)).
  • EdgeInsets (Padding i Margin): Utilitzat per determinar l'espaiat intern o extern al voltant d'un widget.
    • EdgeInsets.all(16.0): Aplica la mateixa distància als 4 costats.
    • EdgeInsets.symmetric(horizontal: 20, vertical: 10): Espaiats per eixos.
    • EdgeInsets.only(top: 12, bottom: 8): Defineix marges de manera individual.
  • BoxDecoration: La classe responsable de pintar el fons d'un Container. Suporta colors plans, degradats (LinearGradient), vores (Border.all()), imatges de fons i ombres (BoxShadow).
  • BorderRadius: Permet aplicar curvatura a les esquinçalls dels contenidors (ex. BorderRadius.circular(16.0)).

6. Bones Pràctiques per a Disseny Responsive

Crear interfícies que s'adaptin correctament a diferents mides de pantalla (mòbils petits, tauletes, escriptori) requereix evitar mides fixes rígides en píxels.

Regles d'Or per al Disseny Adaptatiu en Flutter:
  1. Evita mides fixes elevades: No utilitzis amplades fixes com width: 400 en contenidors centrals. Fes servir layouts flexibles.
  2. Utilitza Expanded i Flexible dins de Row/Column: Evita els errors visuals de franges negres i grogues "overflowed by X pixels" atorgant flexibilitat al contingut sobrant.
  3. Emprera LayoutBuilder: Permet obtenir les restriccions d'espai (amplada/alçària màxima) que el pare atorga al fill per decidir si cal pintar una disposició horitzontal o vertical.
  4. Llegeix el context amb MediaQuery: Proporciona accés directe a les dimensions reals de la pantalla del dispositiu (MediaQuery.of(context).size.width) i a l'orientació (horitzontal/vertical).
  5. Utilitza Wrap en lloc de Row per a col·leccions dinàmiques: Si una fila té massa elements, Wrap fa saltar els elements sobrants automàticament a la línia següent. 
// Exemple d'interfície bàsica responsive amb LayoutBuilder
LayoutBuilder(
  builder: (context, constraints) {
    if (constraints.maxWidth > 600) {
      // Disseny per a Tauleta / Pantalla Gran (Horitzontal)
      return Row(children: [SidebarWidget(), MainContent()]);
    } else {
      // Disseny per a Mòbil (Vertical)
      return Column(children: [MainContent()]);
    }
  },
);

7. Arquitectura Interna: Deep Dive en els 3 Arbres

Una de les preguntes clau en l'enginyeria de Flutter és: Com aconsegueix el framework executar-se a 60/120 FPS de manera fluida si re-crea la interfície contínuament? La clau rau en la seva arquitectura de tres arbres paral·lels.

Quan executem l'aplicació, el framework manté 3 estructures de dades interconnectades amb rols ben definits:

Arbre (Tree) Rol d'Enginyeria Descripció i Funcionament Intern
1. Widget Tree El Plànol
*(Blueprint)*		 És una configuració immutable i ultra-lleugera de la interfície. Descriu com ha de ser la UI en un moment donat. Cada vegada que hi ha un canvi, es destructura i es re-crea de zero sense impactar el rendiment de la memòria.
2. Element Tree El Gestor
*(Manager & Context)*		 És la representació mutable i persistent de l'estructura. Connecta el Widget amb el RenderObject. Guarda l'estat (State) i gestiona el BuildContext. L'Element Tree sobreviu a les re-construccions contínues del Widget Tree.
3. RenderObject Tree El Treballador
*(Worker & Renderer)*		 És l'encarregat del càlcul costós de geometria (Layout), restriccions de mida, zones de contacte tàctil (Hit Testing) i del dibuix dels píxels en pantalla (Painting via Impeller/Skia). Només s'actualitza o re-pinta si l'Element detecta canvis reals.
⚡ Cicle de Reconciliació (*Tree Diffing*) durant el setState():

Quan s'executa un mètode setState() en un StatefulWidget:

  1. L'Element Tree marca el seu node intern com a "brut" (dirty).
  2. En el següent fotograma, el framework executa el mètode build() i genera un nou Widget Tree.
  3. L'Element Tree executa el mètode Widget.canUpdate() comparant el nou widget amb l'antic (comprovant la classe i la Key).
  4. Si coincideixen, l'Element NO es re-crea; simplement actualitza les noves propietats sobre el RenderObject existent, evitant re-pintar tota la pantalla des de zero.
